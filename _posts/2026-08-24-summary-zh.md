### [AI 助力改造非智能升降桌：智能升降、语音控制、多端联动](https://sspai.com/post/113563) ⭐️ 8.0/10

rss · 少数派 \(生活方式与效率\) · 8月24日 07:14

**「背景」** 作者因腰椎问题更换了非智能升降桌，但原厂面板功能有限且无童锁，存在安全隐患。他决定用 ESP32-S3 自制网关，实现多端智能控制。由于现有开源方案（如 Upsy Desky）不兼容他的桌型，他需要逆向分析原厂控制盒与面板之间的 I²C 通信协议。

**「方案」** 作者通过逻辑分析仪抓包，确认控制盒为 I²C 主设备，面板为从设备（地址 0x24），并解析出按键键码（如上升 0x47、下降 0x4F、空闲 0x2E）和数码管段码地址（0x34-0x37）。他用 ESP32-S3 模拟面板，但首次联调失败，发现是缺少上拉电阻（原厂面板上的 2kΩ 电阻被移除），补上后通信恢复。随后，他尝试用软件 I²C 同时响应五个地址以读取高度，但导致运动中断，最终放弃并回退到硬件 I²C，改用双 ToF 传感器（VL6180X 和 VL53L1X）测量高度和障碍物距离。他还实现了双 RJ45 透传原厂面板、OLED 显示、多端控制（Web、REST、键盘、旋钮、手机、手表、语音），并加入童锁和自动童锁功能。

**「启示」** 作者成功将非智能升降桌改造为多端智能控制，并开源了全部代码。他强调了硬件细节（如上拉电阻）和方案取舍（硬件 I²C 稳定性优于软件 I²C）的重要性，为类似改造提供了可复用的经验。

**标签**: `#I2C protocol reverse engineering`, `#ESP32-S3`, `#standing desk automation`, `#embedded systems`, `#hardware hacking`

### [Windows on ARM 原生应用改造指南](https://sspai.com/prime/story/create-your-own-windows-apps) ⭐️ 7.0/10

rss · 少数派 \(生活方式与效率\) · 8月24日 08:28

**「背景」** Windows on ARM 虽已通过转译技术兼容 x86 应用，但转译运行会带来额外开销，导致性能与功耗不如原生。许多常用应用（尤其是国产软件）迟迟未提供 ARM64 原生版本，因此作者探索了自行改造的方法。

**「方案」** 作者发现许多应用基于 Web 技术构建，可通过两种方式实现 ARM64 原生运行。一是将网页直接打包成客户端：对于提供网页版的服务，可使用 PWA 快速安装，或使用开源工具 Pake 在本地编译生成独立的 ARM64 安装包。Pake 基于 Tauri 架构，利用系统 WebView2 渲染，安装包小、内存占用低。二是改造 Electron 套壳应用：通过检查应用目录中的特征（如 app.asar 文件）确认其基于 Electron，然后保留业务代码 app.asar，替换为对应版本的 ARM64 原生 Electron 运行时，并重命名主程序、替换图标和版本信息。作者以「墨刀」为例，演示了从下载免安装包、确认 Electron 版本、下载 ARM64 运行时、复制 app.asar 到修改图标和版本信息的完整流程。

**「启示」** 作者认为，借助 AI 工具和上述方法，非开发人员也能将许多常用应用改造为 Windows ARM64 原生版本，从而提升性能、降低功耗，弥补官方适配的不足。

**「背景」** 本期《派评》汇总了六款近期值得关注的 App，涵盖下载器、网页封装、食物过期追踪、钓鱼天气、AI Agent 远程工具和信息中转站等不同领域。这些应用各有特色，旨在解决日常使用中的具体痛点，但评测深度有限，多为功能描述和用户体验分享。

**「方案」** Motrix 2.0 时隔三年迎来重大更新，采用 Electron、React 和 TypeScript 重写，将下载核心与 UI 分离，支持 Headless Server 部署到 NAS 或云端，并提供 CLI 工具和 AI Agent 调用入口。WebToApp 能在手机上直接将网页打包成独立 APK，支持多种类型和扩展，甚至可运行 Node.js、PHP 等后端服务。Algidy 通过条形码扫描和手动添加追踪食物过期时间，但标签编辑功能尚不完善。不空是一款钓鱼天气分析应用，结合天气和鱼情指数帮助用户判断最佳出钓时机，并支持记录钓点和历史数据。Moshi 允许用户通过手机远程连接 Mac 或 Linux 主机，继续操作 AI Agent，支持多种工具，但跨网络访问需借助 Tailscale。Capture 作为信息中转站，支持从多个入口快速捕获内容，并适配 59 个应用进行针对性导出。

**「启示」** 这些应用展示了工具类软件在细分场景下的创新，但多数仍处于迭代阶段，功能深度和稳定性有待提升。对于追求效率的用户，可根据自身需求选择试用，但需注意部分应用的局限性。

### [iPhone 独立音量控制：快捷指令自动化方案](https://sspai.com/post/112983) ⭐️ 6.0/10

rss · 少数派 \(生活方式与效率\) · 8月24日 03:30

**「背景」** 许多安卓手机支持按应用设置独立音量，但 iOS 系统本身没有此功能。在实际使用中，用户可能希望不同 App 有不同的音量，例如短视频 App 音量较低、视频 App 音量较高，或睡前听书时自动降低音量。作者提出通过快捷指令的自动化来实现类似效果。

**「方案」** 作者利用 iOS 27 新增的储存功能，通过两个自动化实现独立音量控制：打开 App 时，保存当前媒体音量、记录 App 名称，并设置该 App 的指定音量；关闭 App 时，获取当前音量并保存，然后恢复进入前的音量。储存功能使用全局值，以 App 名称和音量作为索引。对于 iOS 27 之前的系统，作者提供了用文件读写替代储存的兼容方案，并提醒关闭“用按钮调整”设置，以确保快捷指令能获取媒体音量而非铃声音量。

**「启示」** 作者认为，通过快捷指令的自动化与储存功能，可以在 iOS 上实现类似安卓的独立音量控制，尽管存在首次音量归零和音量条显示等局限。

**标签**: `#iOS Shortcuts`, `#automation`, `#volume control`, `#iPhone`, `#workflow`
