### [Linux 7.3 提升 VRAM 超量分配性能](https://pixelcluster.dev/VRAM-Overcommit/) ⭐️ 8.0/10

Linux 7.3 引入了针对 VRAM 超量分配的性能改进，旨在解决 GPU 内存受限环境下的内存管理问题。该改进对于图形和 AI 工作负载尤为重要，因为在这些场景中，GPU 内存不足可能导致性能下降或应用崩溃。文章指出，通过优化内核的 VRAM 分配策略，Linux 7.3 能够更高效地处理内存超量分配，减少因内存不足导致的性能瓶颈。这一改进预计将提升在有限 GPU 内存条件下运行大型模型或图形应用的体验。目前，该改进尚未被上游合并，但社区对其前景表示期待。

hackernews · flaburgan · 8月18日 07:51 · [社区讨论](https://news.ycombinator.com/item?id=49342719)

**「背景」** VRAM 超量分配是指操作系统允许应用程序分配超过物理 GPU 内存容量的虚拟内存，并在实际使用时通过分页或交换机制来管理。在 Linux 中，内核负责管理这些内存分配，但传统的分配策略在内存紧张时可能导致性能下降或系统不稳定。Linux 7.3 的改进旨在优化这一过程，通过更智能的分配和回收策略，减少内存碎片和性能损失。

**「影响」** 对于使用 Linux 7.3 的开发者、AI 研究人员和图形应用用户，这一改进将直接提升在 GPU 内存受限环境下的性能，减少因 VRAM 不足导致的卡顿或崩溃。然而，由于该改进尚未上游合并，实际影响取决于后续的集成和硬件兼容性。

**「社区讨论」** 社区对该改进普遍持积极态度，认为这是对 Linux 内核性能的重要提升。一些用户提到，NVIDIA 驱动目前不支持 VRAM 分页，希望未来能有所改善。也有用户对内核内存碎片整理提出疑问，认为可能需要权衡性能。此外，有评论者指出，Linux 内核开发社区中年轻跨性别者的贡献值得关注。

### [Mojo 编程语言正式开源](https://simonwillison.net/2026/Aug/18/mojo-is-now-open-source/) ⭐️ 8.0/10

Mojo 编程语言现已正式开源，其编译器与工具链在 Apache 2.0 许可证下发布。此前，Mojo 在 2023 年 5 月承诺开源，并于上周发布了 1.0 版本，如今兑现了这一承诺。Mojo 最初的目标是成为 Python 的超集，但自 2025 年 8 月起，这一计划有所调整，Mojo 现在定位为独立的语言，专注于简化 GPU 编程，采用受 Python 启发的语法，但并非完全兼容现有 Python 代码。这一开源举措对 AI 和高性能计算领域的开发者具有重要意义。

rss · Simon Willison \(AI 工具\) · 8月18日 21:39

**「背景」** Mojo 由 Modular 公司开发，旨在结合 Python 的易用性与 C/C++ 的性能，特别针对 AI 和 GPU 计算优化。自 2023 年 5 月首次发布以来，Mojo 一直承诺开源，但直到 1.0 版本发布后才正式开源。最初，Mojo 计划作为 Python 的超集，以利用现有 Python 生态，但后来调整为独立语言，专注于 GPU 编程的便捷性。

**「影响」** Mojo 的开源将使 AI 和系统编程领域的开发者能够自由使用、修改和分发该语言，可能加速其在 GPU 编程和高性能计算领域的采用。然而，由于 Mojo 并非 Python 的完全超集，现有 Python 代码的迁移仍需借助 AI 辅助工具，其长期生态发展仍有待观察。

### [AI 递归自我改进可能不会很快到来](https://www.technologyreview.com/2026/08/18/1142188/ai-recursive-self-improvement/) ⭐️ 7.0/10

一项由普林斯顿大学 Peter Kirgis 和 Sayash Kapoor 领导的多机构研究发现，AI 代理尚不具备进行开放式 AI 研究所需的判断力和创造力，这意味着递归自我改进的进程可能比行业预测的要慢。研究采用“影子评估”方法，让 Anthropic 的 Claude Opus 4.8 在六天内、使用 3000 美元 API 额度和 GPU 预算，尝试回答来自 NeurIPS 2026 两篇未发表论文的研究问题，但生成的论文均被原作者拒绝。代理能够完成工程任务，但在提出原创假设、调整研究方向、有效利用资源等方面表现不佳，且无法进行根本性的重新思考。研究指出，当前 AI 的训练方式更适合可自动检查的任务，而开放式研究难以通过强化学习优化。尽管存在样本量小等局限性，该结果与 Anthropic 内部发现相呼应，可能对短期的递归自我改进时间表构成挑战。

rss · MIT Tech Review \(科技前沿\) · 8月18日 09:00

**「背景」** 递归自我改进是指人工智能系统在没有人类干预的情况下改进自身能力的过程，通常被视为实现快速人工智能进步的关键。此前的研究主要评估人工智能在具有明确答案的狭窄任务上的表现，例如解决工程问题或针对基准测试微调模型，而忽略了开放式研究所需的判断力和创造力。为了弥补这一空白，普林斯顿大学的研究人员引入了“影子评估”方法，要求人工智能代理回答来自高质量未发表论文的研究问题，并由原论文作者对其输出进行评分。

**「影响」** 该研究为 AI 行业关于递归自我改进的乐观预测提供了实证反驳，可能促使企业和研究机构重新评估自动化 AI 研究的时间表，并加大对开放式研究能力的投入。
